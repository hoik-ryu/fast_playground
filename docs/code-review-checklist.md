# 코드 리뷰 체크리스트

Sales.AX Boilerplate의 MR 리뷰 기준입니다.  
리뷰어마다 기준이 달라지지 않도록, **5분 안에 훑을 수 있는 수준**으로 유지합니다.

사용법

- 리뷰어: 해당 MR과 관련된 항목만 확인합니다. 무관한 섹션은 건너뜁니다.
- 작성자: MR 올리기 전 셀프 체크로 사용하면 리뷰 왕복이 줄어듭니다.
- 문제를 발견하면 체크 대신 **MR 코멘트로 위치와 이유**를 남깁니다.

관련 문서: [git-convention.md](./git-convention.md) · [frontend-architecture.md](./frontend-architecture.md) · [MR 템플릿](../.gitlab/merge_request_templates/Default.md)

## 1. 기능 검토

- [ ] 요구사항(이슈·MR 설명)을 실제로 충족한다
- [ ] 기존 기능에 회귀 영향이 없다
- [ ] 예외 상황(빈 값, 에러 응답, 로딩, 권한 없음)을 고려했다

## 2. 코드 품질

- [ ] 변수·함수·파일 네이밍이 역할을 드러낸다
- [ ] 복사·붙여넣기 중복이 없다
- [ ] 함수가 한 가지 일만 하고, 지나치게 길지 않다
- [ ] 죽은 코드·주석 처리된 코드·디버그 로그가 없다
- [ ] 주석 대신 코드로 설명되고 있다 (주석은 '왜'만 남긴다)

## 3. React / Frontend

- [ ] 상태의 위치가 적절하다 (서버 상태는 Query, 로컬 상태는 컴포넌트)
- [ ] React Query 사용이 적절하다 (Query Key 규칙, `staleTime`, 무효화 시점)
- [ ] 불필요한 리렌더링이 없다 (의존성 배열, 인라인 객체·함수 남용)
- [ ] 컴포넌트 분리 단위가 적절하다 (과분리·거대 컴포넌트 모두 지양)
- [ ] FSD-lite 레이어와 의존 방향을 지켰다 (`app → pages → features → entities → shared`)
- [ ] import alias와 barrel(public API) 규칙을 따랐다

## 4. Backend

- [ ] API 응답 형식이 기존 엔드포인트와 일관적이다
- [ ] 요청 Validation(Pydantic 스키마)이 충분하다
- [ ] 예외 처리와 HTTP 상태 코드가 적절하다
- [ ] DB 접근이 적절하다 (세션 관리, 트랜잭션 범위, 불필요한 쿼리 없음)
- [ ] 인증·권한 체크가 필요한 엔드포인트에 적용되어 있다
- [ ] 스키마 변경 시 Alembic 마이그레이션이 함께 있다

## 5. 성능

- [ ] 불필요·중복 API 호출이 없다
- [ ] 불필요한 `useEffect`가 없다 (파생 값은 렌더 중 계산)
- [ ] N+1 쿼리 문제가 없다 (관계 로딩 전략 확인)
- [ ] 캐싱·무효화 전략이 데이터 성격에 맞다
- [ ] 큰 목록·이미지 등 무거운 렌더링에 대한 고려가 있다

## 6. 보안

- [ ] 인증/인가가 프론트·백엔드 양쪽에서 적절하다 (프론트 숨김만으로 끝내지 않음)
- [ ] 토큰·비밀번호·키 등 민감 정보가 코드·로그·응답에 노출되지 않는다
- [ ] SQL Injection 위험이 없다 (ORM·바인딩 파라미터 사용, 문자열 조합 쿼리 금지)
- [ ] XSS 위험이 없다 (`dangerouslySetInnerHTML` 등 직접 HTML 주입 금지)
- [ ] 에러 메시지가 내부 구조를 과하게 노출하지 않는다

## 7. 테스트 · 검증

현재 저장소에서 실행 가능한 검사입니다.

**Frontend** (`cd frontend`)

- [ ] `pnpm lint` 통과
- [ ] `pnpm typecheck` 통과
- [ ] `pnpm build` 통과
- [ ] 로컬 동작 확인 (`pnpm dev`)

**Backend** (`cd backend`)

- [ ] `uv run ruff check` 통과
- [ ] `uv run ruff format --check` 통과
- [ ] API 동작 확인

**자동화 테스트** — 아직 미구축이므로 지금은 확인하지 않습니다.

- [ ] Frontend unit/e2e 테스트 — _구축 후 확인_
- [ ] Backend pytest — _구축 후 확인_

## 리뷰 코멘트 작성 가이드

- **must**: 머지 전 반드시 반영 (버그·보안·규칙 위반)
- **should**: 반영 권장, 합의되면 후속 처리 가능
- **nit**: 취향·사소한 개선. 반영은 작성자 재량

예: `must: 토큰이 로그에 그대로 찍힙니다. 마스킹이 필요합니다.`
